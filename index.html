Bank statement review system Production

BeforeStaff read every bank statement line by line and typed each payer into a spreadsheet.
AfterUpload the file. The system lists incoming payments and likely payers; the team approves, corrects or rejects.
  • Python OCR and layout reader for different banks' formats, scanned pages and receivables reports.
  • Approved results sync to the case trackers on their own; a correction updates the same row instead of adding a duplicate.
  • Team corrections are stored and fed back, and a weekly review turns repeat mistakes into fixes.
  • Logins with roles, audit log, undo and restore, error alerts, nightly backups, hardened Linux server.

Registered agent research agent Pilot

BeforeSearch each state's business website, one company at a time, for about 500 companies.
AfterFree government data first, an LLM agent with web search only for the rest. Every answer comes with a source and a quote.
  • Picked the model by testing four inside the real agent on companies with known answers, not by benchmarks.
  • Answers must match a fixed format; failures retry, then switch to a backup model, with a circuit breaker if errors pile up.
  • Only a company name and state ever leave the firm; web content is treated as untrusted data.
  • Pilot: agent found for 21 of 24 companies, each one approved by a reviewer.

How I work

The same few rules show up in everything I build.

Cheapest reliable source first

Free official data and plain code before an AI model, and a small model before a big one.

The AI copies, the code judges

Models extract and summarize. Business rules live in code with tests, where they can't quietly drift.

People approve what matters

Nothing goes out without a person signing off, and their corrections teach the system.

Test before it ships

Old and new versions run side by side on real files before a change goes live.
